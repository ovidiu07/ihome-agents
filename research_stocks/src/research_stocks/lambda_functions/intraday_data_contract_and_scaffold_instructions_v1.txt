INTRADAY REPORT — trader‑friendly, JSON‑grounded (v3.5 · 2025‑08‑12 · Full‑JSON Ingestion, Strict Provenance)

Goal: Produce a concise, fully‑actionable intraday trading report that
(1) uses ONLY values present in the provided JSON,
(2) may optionally consume the prior daily MD (SECTION 1 JSON only) for bias/guardrails/open base,
(3) silently analyzes ALL available data across intraday timeframes (60m/15m/5m/1m),
(4) enumerates ALL patterns found in EVERY finnhub_* / fintech_* block with status + next‑use guidance,
(5) outputs numeric, decision‑ready playbooks and a plain‑English next‑price map,
(6) performs INTERNAL completeness checks so nothing in JSON is ignored (levels, patterns, setups, indicators, session extremes, candles),
(7) enforces HARD provenance for printed levels (no interpolation or invented numbers) and clean fallbacks for missing anchors.
No invented numbers.

------------------------------------------------------------
INPUTS
------------------------------------------------------------
* intraday_json: A single JSON object with any number of timeframe blocks.
  A timeframe block is any top‑level key matching ^(finnhub_|fintech_).
  Examples: finnhub_one_minute, finnhub_five_minutes, finnhub_fifteen_minutes, fintech_hourly, fintech_daily, fintech_weekly.
  Each block may include: candles (OHLCV with UTC timestamps), technical_indicators OR signals (name/value/direction),
  support_resistance.levels, session_high, session_low, last_open, last_close, last_volume, bias (optional), summary (optional, prose only),
  patterns_explained[] (array), setups[] (optional), vwap (optional), atr/atr5 (optional), last_timestamp_utc (optional).

* previous_daily_report_md (OPTIONAL):
  Use ONLY SECTION 1 JSON to extract:
  - daily_bias (and score S if provided),
  - structural_range.low/high (guardrails),
  - current_day.open as OPEN_BASE,
  - optional trade_plans[] (carry over only if those prices also exist in intraday_json).
  Ignore prose and any numbers not present in intraday_json.

------------------------------------------------------------
STRICT DATA POLICY & FALLBACKS
------------------------------------------------------------
* Use ONLY values from intraday_json and OPEN_BASE (if available). Never cite external data. No invented numbers.
* Rounding: prices to 2 decimals (round‑half‑up). Volume: integer. Percents to 2 decimals.
* Latest anchors (deterministic fallbacks):
  - LAST_TF = finest available among {1m→5m→15m→60m}.
  - LAST_O: prefer LAST_TF.last_open; else LAST_TF.candles[-1].o.
  - LAST_C: prefer LAST_TF.last_close; else LAST_TF.candles[-1].c.
  - LAST_V: prefer LAST_TF.last_volume; else LAST_TF.candles[-1].v; else UNRESOLVED.
  - HI_SESSION: max over all present blocks of session_high; if none, max of all candles.h across present blocks.
  - LO_SESSION: min over all present blocks of session_low; if none, min of all candles.l across present blocks.
  - last_updated_utc: prefer LAST_TF.last_timestamp_utc; else LAST_TF.candles[-1].t; else UNRESOLVED.
* When an anchor is UNRESOLVED:
  - Do NOT print placeholder text like “no data”.
  - Section 1 formatting adapts:
    • If last_updated_utc unresolved → print a dash “—” in its place.
    • If LAST_V unresolved → omit the “ V:…” token entirely.
* VWAP selection: prefer a numeric vwap from 5m→15m→1m. If none exist, treat VWAP as unavailable and do not mention it anywhere.
* ATR5 bands: If ATR5 exists in any block, select from 5m→15m. Define B15=0.3×ATR5, B50=0.5×ATR5, B85=1.0×ATR5.
  If no ATR5, omit bands and ATR‑derived targets entirely.
* Time & freshness: use last_updated_utc for staleness; if unavailable, skip freshness checks and do not warn about freshness.
* Tick size: infer from price precision if provided; else default tick_size = 0.01 for dedupe heuristics.

------------------------------------------------------------
TIMEFRAME DISCOVERY & PRIORITY
------------------------------------------------------------
* Detect ALL ^(finnhub_|fintech_) blocks and process each.
* Do not ignore any present field (levels, candles, sessions, patterns, setups, indicators, biases).
* Intraday Bias S uses 4‑TF context when available: 60m=0.35, 15m=0.35, 5m=0.20, 1m=0.10. Renormalize if missing TFs.
  1m cannot flip direction alone.

------------------------------------------------------------
INDICATOR INGESTION & SCORING (INTERNAL — DO NOT PRINT TABLES)
------------------------------------------------------------
* Ingest everything:
  - Read ALL entries from technical_indicators and/or signals.
  - Lowercase names; trim spaces/underscores; keep original name for display in drivers.
  - Alias map (extendable):
    • rsi → {rsi}
    • stoch → {stoch, stoch_k, stoch_d, stoch_slowk, stoch_slowd}
    • macd → {macd, macd_hist, macd_signal}
    • adx/dmi → {adx, dmi, +di, -di}
    • ma → {sma, ema, wma, hma, kama}
    • atr → {atr, atr5}
    • bbwidth → {bbwidth, bb_width, boll_width, bbands_width}
    • vwap → {vwap}
    • flow → {obv, mfi, cmf, vortex, +vi, -vi}
    • ta_signal → {bias, ta_signal}
    • others → any unmatched names.
* Direction & normalization:
  - If direction exists: rising=+1, falling=−1, flat=0.
  - Else infer sign from change vs prior indicator point if available; else 0.
  - Normalize per type (RSI/STOCH, MACD, ADX, MAs, ATR/BB width, Flow, Unknown as bounded or z‑scored).
  - Block‑level bias/ta_signal: map bullish→+0.25, bearish→−0.25 contribution cap for that TF.
* Aggregation to Intraday Bias S:
  - Per‑TF composite = weighted average of indicator scores in that TF (drop NaNs).
  - Combine across TFs by TF weights above. Neutrality guard: if |S|<0.15 or fewer than two of {5m,15m,60m} agree → headline Bias = Neutral (still print S).
* Top drivers (display, max 5):
  - Choose by absolute contribution = |indicator_score × TF_weight|. Print as name@TF (use original JSON names), deduped.

------------------------------------------------------------
LEVELS (DISCOVERY, DEDUPE, SELECTION) — HARD PROVENANCE
------------------------------------------------------------
* Collect candidate levels from EVERY block:
  - support_resistance.levels (numeric),
  - session_high / session_low,
  - explicit swing highs/lows if provided in the block (e.g., “recent_high(candle t=-1)”).
  Tag each candidate with its source TF and source type {levels|session|swing}.
* Dedupe: merge levels closer than max(0.10% of LAST_C, 2×tick_size). Prefer higher TF, more touches, session extremes.
* S1/R1 selection for sections 3 & 4:
  - Primary search across {5m, 15m, 60m}. Pick S1 = nearest support below LAST_C; R1 = nearest resistance above LAST_C.
  - If a side is missing after the primary search, fallback to 1m. If still missing, declare “no level” for that side.
* HARD provenance check before printing S1/R1:
  - The exact 2‑dec‑rounded value MUST match one of the collected candidate prices.
  - If not, replace with the nearest candidate that DOES match. Never interpolate or invent.
* “Key Levels” prints exactly 2 supports and 2 resistances (S1/S2/R1/R2) around LAST_C after dedupe, each with rationale:
  (TF=<block>; source=<levels|session|swing>).

------------------------------------------------------------
PATTERNS (EXHAUSTIVE, DEDUPED, HUMAN‑READABLE)
------------------------------------------------------------
* For EVERY block, read patterns_explained[]. If empty/absent → print exactly: — <TF key> (0 patterns).
* Deduplicate patterns by {name, type, status, entry, stop, first target}. List duplicates once.
* Normalize status to {completed, successful, invalidated, failed, inprogress, waiting}.
* STRUCTURE (strict): TF order 60m, 15m, 5m, 1m (include only TFs present).
  — <TF key> (<count> patterns)
    • Facts: <patternname> (<type>) — Status: <status> — Entry=<entry>, Stop=<stop>, TP1=<t1>[, TP2=<t2>]
    • Plain English: one sentence (Grade‑8) on how to use or avoid it now. If any of Entry/Stop/Targets is zero/missing → say “context‑only”.
* Coverage header (must match counts): “Coverage: 60m={{c60}}; 15m={{c15}}; 5m={{c5}}; 1m={{c1}}” (only include TFs present).
  If counts don’t match JSON, regenerate the digest.

------------------------------------------------------------
SETUPS (IF PROVIDED)
------------------------------------------------------------
* If any block has setups[] with numeric entry & stop and ≥1 target, seed at least one playbook in Section 5 directly
  from the best setup (closest Entry to LAST_C; TF preference 5m→15m→60m→1m).
* Direction for setup‑anchored plan = sign(T1 − Entry) (Long if >0; Short if <0). If ambiguous, mark “context‑only” and do not print.
* Use the setup’s Entry/Stop/Targets EXACTLY as in JSON; never modify.

------------------------------------------------------------
TRADE DECISION ENGINE (NUMERIC, HUMAN‑FRIENDLY)
------------------------------------------------------------
Allowed numeric sources: {VWAP (if available), session_high, session_low, last_open, last_close,
support_resistance.levels, patterns_explained Entry/Stop/Targets, OPEN_BASE}. ATR bands only when ATR5 exists.
Always try to output ≥1 long and ≥1 short plan unless you must print “No‑trade: insufficient edge” with the reason.

1) Breakout Long
   Conditions: S>0, VWAP available and price>VWAP, ADX(5m)≥20, RSI(5m)>55, and latest 5m close > R1.
   Playbook: “At R1 ({{R1}}), wait for a 1‑min CLOSE ABOVE R1. If the next bar does not close back below R1, ENTER LONG.
   Stop: below max(VWAP, S1). Targets: ATR‑based if ATR5, else nearest resistance ladder.”

2) Pullback Long to Support
   Conditions: S>0 and price near S1 (within 0.6×ATR5 if ATR exists; else within 0.10% of price).
   Playbook: “At S1 ({{S1}}), after two 1‑min RED candles, buy the first 1‑min CLOSE back above Entry{{ if VWAP available: " or above VWAP"}}.
   Stop: below S1. Targets: ATR‑based if ATR5, else R1 then R2.”

3) Breakdown Short
   Conditions: S<0{{ if VWAP available: ", price<VWAP"}}, ADX(5m)≥20, RSI(5m)<45, and latest 5m close < S1.
   Playbook: “If price loses S1 ({{S1}}) on a 1‑min close and cannot reclaim it next bar, ENTER SHORT.
   Stop: above min(R1{{ if VWAP available: ", VWAP"}}). Targets: ATR‑based if ATR5, else S2 then next support.”

4) Mean‑Revert Short at Resistance
   Conditions: S≥0 but overbought (e.g., RSI>70) AND clear rejection at R1/R2.
   Playbook: “At R1/R2, if two 1‑min GREEN candles fail to close above the level and the next bar closes back below, ENTER SHORT.
   Stop: above next resistance. Targets: {{ if VWAP available: "VWAP then"}} S1.”

Setup‑Anchored Plan (optional, if setups[] valid):
   Mirror the chosen setup’s Entry/Stop/Targets exactly; label Long if T1>Entry else Short. If any required number is missing, do not print this plan.

Invalidation:
   Provide one numeric level where the thesis is wrong (must be one of the printed levels or the printed Stop).
   Bullish plans invalidate on close below their stop/support; Bearish on close above their stop/resistance.

No‑trade:
   Only print if (a) stale beyond threshold OR (b) both VWAP and ATR5 are unavailable and no setup‑anchored plan passes provenance.

------------------------------------------------------------
RELIABILITY GUARDRAILS
------------------------------------------------------------
* Numeric–prose consistency: do not write “above X” unless close > X; do not write “below X” unless close < X.
* Provenance: every Entry/Stop/Target comes from the allowed sources; ATR offsets only if ATR5 exists.
* Plan pruning: drop any plan that fails provenance. If none remain, print “No‑trade: insufficient edge” + reason.
* Confidence caps:
  – If fewer than two of {5m,15m,60m} align, cap |S| at 0.30 and plan confidence at 0.45.
  – If ADX@60m < 20 and ADX@1D < 20 (when both exist), cap plan confidence at 0.40.
* Symbol anchoring: use top‑level symbol verbatim.
* Rounding: all printed prices to 2 decimals (round‑half‑up).

------------------------------------------------------------
COMPLETENESS CHECKS (INTERNAL — MUST PASS BEFORE OUTPUT)
------------------------------------------------------------
* Blocks: every detected ^(finnhub_|fintech_) block processed at least once.
* Patterns: counts per TF in output header match JSON after dedupe; if mismatch, regenerate digest.
* Setups: if setups[] exist with valid numbers, at least one setup‑anchored plan appears in Section 5 (unless provenance fails).
* Levels: S1/R1 chosen after aggregating candidates from ALL present TFs (with dedupe). If a printed level does not match a candidate (post‑rounding), re‑select a valid candidate.
* Anchors: LAST_O/LAST_C resolved via fallbacks. If LAST_V unresolved → omit “ V:…” in Section 1. If last_updated_utc unresolved → print “—” as timestamp and skip freshness warning.
* VWAP/ATR: if absent, never mention them (including in rules, targets, or prose).
