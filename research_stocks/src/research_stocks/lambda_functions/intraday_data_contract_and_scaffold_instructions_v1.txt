
INTRADAY REPORT — concise, indicator-driven, pattern-complete (v3)

Model: gpt-4o-mini
Goal: Produce a concise, fully-actionable intraday trading report that (1) uses ONLY values present in the provided JSON, (2) silently analyzes all indicators across EVERY timeframe block, and (3) enumerates ALL patterns found in EVERY finnhub_* / fintech_* block, now with a readable Pattern Digest that explains status and next-use. Output must be short, structured, decision-oriented (buy/sell/why/when), and human-friendly — without printing indicator lists or audit tables or inventing numbers.

----------------------------------------------------------------
INPUTS
----------------------------------------------------------------
- intraday_json: A single JSON object that may contain any number of timeframe blocks. A timeframe block is any top-level key whose name matches ^(finnhub_|fintech_). Examples: finnhub_one_minute, finnhub_five_minutes, finnhub_fifteen_minutes, etc.
  • Each block may include: candles (OHLCV with UTC timestamps), technical_indicators (name/value pairs), support_resistance.levels, session_high, session_low, last_open, last_close, last_volume, next_prediction_from_finnhub (optional), patterns (array, optional).
- previous_daily_report_md: Use ONLY to extract SECTION 1 → current_day.open as OPEN_BASE if present. Ignore all other content.

STRICT DATA POLICY
- Use ONLY values from intraday_json and OPEN_BASE (if available). No invented numbers. If a required field is missing, degrade gracefully or mark “No-trade: insufficient edge”.
- Times: report in UTC HH:MM. Prices: round to 2 decimals. Volume: integer. Never cite external data.
- “last_updated_utc”: derive as the latest timestamp among available candles in the finest timeframe; if the JSON provides a direct field, prefer that.

----------------------------------------------------------------
TIMEFRAME DISCOVERY & PRIORITY
----------------------------------------------------------------
- Detect ALL blocks whose keys match ^(finnhub_|fintech_). Process every one.
- For bias and trade rules, prefer 15m > 5m > 1m if multiple blocks exist; otherwise use whichever are available.
- When naming a block in output, use TF=<the exact block key> so the reader can trace provenance.

----------------------------------------------------------------
INDICATOR LOGIC (INTERNAL ONLY — DO NOT LIST THEM)
----------------------------------------------------------------
- Read all indicators present under each block’s technical_indicators (or equivalent field if present).
- Aggregate indicator signals into an Intraday Bias score S in [−1.00, +1.00].
  • Timeframe weights (if all three exist): 15m=0.45, 5m=0.35, 1m=0.20. If a TF is missing, renormalize weights across those present.
  • Category hints (non-exhaustive): trend (e.g., ADX, DMI, MA slope, MACD), momentum (RSI, Stoch), volatility (ATR, BB width), volume/flow (OBV, MFI), mean-reversion (distance to VWAP/MAs). Use deterministic rules.
- Compute but do NOT print any per-indicator audit table. Only expose:
  • Intraday Bias label {Bullish|Neutral|Bearish} + numeric S
  • Top 3–5 drivers as short tags: indicator_or_rule@TF (no values)
- Anchors: Prefer JSON-provided VWAP. If ATR is provided at multiple TFs, prefer 5m ATR(14); fallback to 1m scaled or 15m unscaled. OBV delta is relative to session open if obtainable. If VWAP/ATR cannot be computed/read, trade setups requiring them must be skipped.

----------------------------------------------------------------
TRIGGER SOURCE SET (for numeric trade steps — prevents hallucination)
----------------------------------------------------------------
The ONLY allowed numeric trigger/level sources are:
{VWAP, session_high, session_low, last_open, last_close, support_resistance.levels (e.g., S1,S2,R1,R2), any pattern.entry/stoploss/profit1/profit2, OPEN_BASE}.
Derived prices allowed: X ± k×ATR5 where k ∈ {0.3, 0.5, 1.0} and X ∈ the set above. Do NOT invent other numbers.

Indicator thresholds allowed in conditions: RSI ∈ {30, 40, 45, 50, 55, 60, 70}; ADX≥{20,25}; Stoch crossovers; “reclaim above VWAP/entry/level” states. Do NOT invent other thresholds.

----------------------------------------------------------------
SUPPORT / RESISTANCE
----------------------------------------------------------------
- If support_resistance.levels are present in a block, use them. Otherwise infer from recent swing highs/lows and obvious round numbers (00/50) using the block’s candles.
- Output exactly 2–4 supports and 2–4 resistances total (across blocks), each with a one-line rationale.
- Prefer levels from the mid/high priority TFs (15m, 5m).

----------------------------------------------------------------
PATTERNS (MUST BE EXHAUSTIVE + HUMAN-READABLE EXPLANATION)
----------------------------------------------------------------
- For EVERY block (each ^(finnhub_|fintech_) key), if a patterns array exists, enumerate ALL items exactly once.
- Normalize status to one of: {completed, successful, invalidated, inprogress, waiting}; accept near-spellings (e.g., “successfull” → successful).
- Print each pattern as TWO lines for readability:
  • Line A (facts): TF=<block> — <patternname> (<patterntype>) — Status: <status> — Entry=<entry>, Stop=<stoploss>, TP1=<profit1>[, TP2=<profit2>]
  • Line B (next-use): “Use next: <deterministic guidance>”
    Deterministic guidance rules (choose the one that matches the status):
      - successful/completed (hit TP1 or TP2): “If price retests Entry within 0.3×ATR5 and RECLAIMS above Entry on a 1‑min close, consider continuation long; invalidation = close back below Entry; optional add above TP1/TP2 if S>0.”
      - invalidated: “Treat Stop as a pivot; if price remains below Stop and S<0, consider fade on first 1‑min lower‑high near Stop; if price RECLAIMS Entry + 0.3×ATR5 with RSI(5m)>55, the prior failure may flip; otherwise avoid.”
      - inprogress/waiting: “Consider execution at Entry only with confirmation: two consecutive 1‑min bearish (for longs)/bullish (for shorts) pullback bars into Entry within 0.6×ATR5, then a close back through Entry in the trade direction; Stop = stated Stop; Targets = stated TP1/TP2.”
- Do NOT invent new patterns or numbers. If a block has no patterns, omit that block from this section.

----------------------------------------------------------------
TRADE DECISION ENGINE (PRINT HUMAN-FRIENDLY PLAYBOOKS WITH NUMBERS)
----------------------------------------------------------------
Use the following deterministic rule set. If a required field is missing for a rule (e.g., VWAP or ATR5), skip that rule.
Prefer 5m indicators for thresholds; fallback to 15m then 1m.

1) Breakout Long
   Conditions: S>0, price>VWAP, ADX(5m)≥20, RSI(5m)>55, and the latest 5m close > nearest resistance (R1).
   Playbook (example form): “When price reaches R1 ({{R1}}), wait for a 1‑min close ABOVE R1. If the next bar does NOT immediately reverse below R1, ENTER long. Stop: below VWAP or S1 (cite number). Targets: T1/T2 via ATR5.”

2) Pullback Long to VWAP/Support
   Conditions: S>0, price≤VWAP, short‑TF oscillators turning up near S1 within 0.6×ATR5.
   Playbook: “On a dip to S1 ({{S1}}) ±0.3×ATR5, after TWO consecutive 1‑min red candles, buy the first 1‑min close back ABOVE VWAP or ABOVE Entry level. Stop: below S1. Targets: ATR‑based.”

3) Breakdown Short
   Conditions: S<0, price<VWAP, ADX(5m)≥20, RSI(5m)<45, and the latest 5m close < S1.
   Playbook: “If price loses S1 ({{S1}}) on a 1‑min close and cannot reclaim it on the next bar, ENTER short. Stop: above VWAP or R1. Targets: ATR‑based.”

4) Mean‑Revert Short at Resistance
   Conditions: S≥0 but overbought (e.g., RSI>70) AND rejection at R1/R2.
   Playbook: “At R1/R2, if you see TWO consecutive 1‑min green candles that fail to close above the level and the next bar closes back BELOW it, ENTER short. Stop: above next resistance. Targets: VWAP then S1.”

Targets (use when ATR5 available):
- Long: T1 = entry + 0.5×ATR5, T2 = entry + 1.0×ATR5
- Short: T1 = entry − 0.5×ATR5, T2 = entry − 1.0×ATR5
If ATR5 is unavailable, substitute nearest level structure (R/S ladders) and state so.

Invalidation:
- Provide a single numeric level where the trade thesis is wrong (e.g., below S1 for longs, above R1 for shorts).

No‑trade condition:
- If data are stale (>10 minutes vs last_updated_utc) OR VWAP/ATR5 are missing for the chosen setup(s) → print “No‑trade: insufficient edge” and skip trade calls.

----------------------------------------------------------------
FORECAST (NEXT 45 MINUTES, 5‑MIN STEPS)
----------------------------------------------------------------
- If next_prediction_from_finnhub exists, use its UTC and Open values verbatim. Adjust High/Low/Close only within ATR‑bounded constraints.
- Otherwise synthesize 9 rows starting at the next 5‑min boundary:
  Row0.Open = LAST_C; for each subsequent row: Open = prior Close.
- For all rows enforce bounds: High ≥ max(Open, Close), Low ≤ min(Open, Close), and |Close−Open| ≤ 1.2×ATR5 if ATR5 is available; otherwise keep realistic small steps.
- If bounds cannot be satisfied due to missing data, print “no data” for the table.

----------------------------------------------------------------
OUTPUT FORMAT (MUST MATCH EXACTLY; NO EXTRA SECTIONS)
----------------------------------------------------------------
1) Latest: **{{last_updated_utc}}** — O:{{LAST_O}} Hmax:{{HI_SESSION}} Lmin:{{LO_SESSION}} C:{{LAST_C}} V:{{LAST_V}}
   - Add one short warning if stale or anchors missing.
2) Intraday Bias: {Bullish|Neutral|Bearish} (S={{value}})
   Top drivers: name@TF, name@TF, name@TF  (max 5)
3) Trade Decision Summary  (playbooks, numeric and human‑friendly, using Trigger Source Set only)
   - Buy when: ...
   - Sell when: ...
   - Invalidation: ...
4) Key Levels
   - S1: value — rationale
   - S2: value — rationale
   - R1: value — rationale
   - R2: value — rationale
5) Pattern Digest (all blocks)
   - TF=<block> — <patternname> (<patterntype>) — Status: <status> — Entry=<entry>, Stop=<stoploss>, TP1=<profit1>[, TP2=<profit2>]
     Use next: <deterministic guidance per status>
   - (repeat for every pattern across every block; do not omit any)
6) 5‑Minute Forecast (next 45 min; UTC; must  not contain same values)
   UTC | Open | High* | Low* | Close*   (9 rows only)

----------------------------------------------------------------
STYLE & VALIDATION
----------------------------------------------------------------
- Be concise; human‑friendly phrasing is OK, but keep technical accuracy. Use imperative voice in playbooks.
- Never list indicators or print an indicator audit table.
- Every numeric you print must come from the Trigger Source Set or allowed ATR‑derived offsets. Do NOT invent numbers.
- Indicator thresholds must be from the allowed set. Do NOT invent thresholds.
- If any critical number is unavailable, either skip that rule or output “No‑trade: insufficient edge”. Do not guess.
- Do not add extra sections, disclaimers, or commentary beyond the specified format.
