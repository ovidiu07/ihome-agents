## Hard rules (numeric hygiene)
1) **Numbers only from structured fields.** Use only numeric values from `signals[].value`, `levels.*[].price`, `setups.*`, `patterns_explained.*`. Do **not** extract numbers from free text (e.g., `summary`, `comment`).
2) If a number is missing, print **N/A** (or `null` in JSON) and proceed; never invent values or compute ATR/offsets unless provided as a numeric signal.
3) Prefer **Daily (1D)** for context and structural levels; use **60m/15m** for confirmations, triggers, and setups. If TFs conflict, **favor higher TF** (1D > 60m > 15m > 5m > 1m).
4) Treat zero‑only arrays or `0.0` placeholders as **unavailable**.
5) **Deduplicate** exact duplicate level prices; keep the most informative `why`.
6) “Session” levels may appear inside each timeframe block (e.g., `"session_high"`, `"session_low"`). If present, tag them `(session)` and prioritize them at the top of Daily levels. Do **not** rely on missing top‑level `session_high/low` fields.

## Indicator Audit (present‑only)
- Build the audit from **signals[]** already provided per TF. Do **not** enumerate indicators that are not present. Do **not** synthesize values from other arrays unless explicitly numeric.
- Show at most these families when present: **MA (SMA/EMA/WMA/DEMA)**, **Momentum (RSI/MACD)**, **Trend (ADX)**, **Oscillators (STOCH/MFI)**. Other indicators should be included if provided in `signals[]`.
- For each TF (D/60m/15m), the table fields are: `Indicator | TF last | TF dir`. Use the given `value` and `direction` as-is.

## Bias computation (deterministic, signals‑only)
- Map indicators to families: MA→0.30, Momentum (RSI/MACD)→0.25, Oscillator (STOCH/MFI)→0.15, Trend (ADX)→0.30.
- TF weights: 1D=0.50, 60m=0.30, 15m=0.20. (If a TF missing, its weight=0.)
- Per non‑neutral signal: score = (+1 for rising/bullish tilt, −1 for falling/bearish tilt) × family_weight × TF_weight.
- Normalize by maximum possible for **present** signals and clip to [−1, +1].
- Output textual bias buckets: **Bullish if S>0.25**, **Neutral if −0.25≤S≤0.25**, **Bearish if S<−0.25**.

## Forecast Engine (conditional; no ATR synthesis)
- Run the Forecast Engine if the **Daily** block contains an ATR signal named **`ATR.atr`**, **`ATR`**, or **`ATR_D14`** (case-insensitive).
- **Implementation note:** set `atr_value` to the value of the first Daily signal in `signals` whose `name` matches **`/^ATR(\.atr)?$/i`** or **`/^ATR_D\d+$/i`**.
- If no such signal is present, set **R_base: N/A** and **skip OHLC predictions** (use `null` for `current_day` and `weekly_forecast` fields in SECTION 1 JSON).

## Trade Plan generation (machine‑usable + human)
You MUST output machine‑usable trade plans in SECTION 1 and a human playbook in SECTION 3. Use ONLY prices already present in `levels.*[].price` or `patterns_explained` fields.

**Constraints (hard):**
- Max 3 plans. Name each plan `Momentum Breakout`, `Reversal`, or `Pullback`.

- `source_tf` ∈ {`1m`,`5m`,`15m`,`60m`,`1D`,`1W`} and must match the origin of the referenced price.
- Gate momentum trades with trend quality: if **ADX@60m < 20** AND **ADX@1D < 20** (when both present), cap plan `confidence` ≤ 0.40.
- 1m is only for execution timing/micro‑scalp; never the sole directional driver.
- Invalidation must reference the same-side level used as stop (no invented numbers).
- No numeric trailing stops unless equal to an existing printed level.

**Selection rules:**
- Prefer plans aligned with final Daily bias.
- If plans conflict, keep the two with highest TF importance (1D>60m>15m>5m).
- If no credible prices exist, omit the plan instead of inventing numbers.

**Confidence calibration:**
- Base = |S| from Bias computation (if S is N/A, use 0.30 by default).
- +0.1 if plan aligns with both 1D and 60m biases.
- −0.1 if ADX@60m < 18 (when present) or Weekly opposes the plan.
- Clip to [0,1].
